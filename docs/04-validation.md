# 검증 보고서

검증일: 2026-10-23. 환경: macOS, Node.js 22.23.3, Three.js 0.180.0, Vite 7.3.7, Ego Lite 0.6.0.12. 실제 설치 버전은 `package-lock.json`을 기준으로 한다. 브라우저 조작은 전부 **Ego Lite / ego-browser**에서 수행했다.

## 결과

- 자동 테스트 **26개 통과**, 실패 0개.
- 프로덕션 정적 빌드 성공.
- 브라우저에서 **20개 전투 전부 출전·병력 생성·목표 표시·사령부 복귀 확인**.
- 브라우저 기능 검사 **28개 통과**, 수집한 JavaScript 실행 오류 0개.
- 도감·무기·기록·설정·역사 상세 메뉴 검사 **7개 통과**.
- 실제 입력으로 언성 영웅전을 플레이해 목표 달성, 승리 결과, 훈장·기록 저장을 확인.
- 390×844 세로 사령부와 844×390 가로 전투 화면에서 가로 넘침 없음. 화면 이동 버튼을 누르고 유지해 실제 영웅 좌표가 3단위 이상 변하는 것을 확인.

이 결과는 모든 전투의 모든 전술 조합을 사람이 끝까지 플레이했다는 뜻은 아니다. 전체 전장 생성·진행 검사, 목표별 실제 시뮬레이션 검사, 대표 전투의 실제 브라우저 완주를 조합했다. 휴대전화는 Ego Lite의 viewport·터치 에뮬레이션으로 검증했고 실제 기종별 GPU·오디오 출력은 별도 기기 시험 범위다.

## 자동 테스트 범위

`npm test`는 Node의 내장 테스트 실행기를 사용한다. 엔진 검사에서는 실제 Three.js 장면 그래프와 실제 `Battlefield` 메서드를 호출한다. DOM/WebGL 렌더러를 흉내 내어 화면 성공을 주장하지 않는다. 렌더링과 입력은 별도의 Ego Lite 검사로 확인했다.

| 묶음 | 검증 내용 |
|---|---|
| 병력·상태 | 도감과 실제 생명력 일치, 6병종, 좌·우 부장과 지휘 범위, 화면 좌표의 유한성 |
| 전투 | 실제 기술 피해·격파·회복·재사용 시간, 일시정지 제한, 적장의 실제 피해 |
| 지형 | 고지 이동 감소, 습지에서 기병의 추가 감속, 숲 궁병 사거리, 교량 경로와 수면 충돌 |
| AI | 아군 전멸 후 멀리 있는 지휘관 추적, 교량 전투 중 강 수면 진입 방지 |

| 호송 | 장판 두 NPC 생성·실제 이동·치유·귀환, 적의 공격, 한 명 사망 시 패배 |

## 실제 브라우저 검사

### 전장과 메뉴

각 전투의 모드와 전투 버튼을 클릭하고 출전해 실제 상태와 목표가 존재하는지 확인한 뒤 일시정지 메뉴로 복귀했다. 이후 확대 버튼, 축소 버튼, 실제 마우스 휠, M 전술 시점, 좌군 지휘, 일시정지 중 시간·기술 정지, 지도 종료 상태를 확인했다.

- [`evidence/browser-smoke-checks.json`](evidence/browser-smoke-checks.json): 28개 검사와 실행 오류 수집 결과.
- [`evidence/browser-menu-checks.json`](evidence/browser-menu-checks.json): 병종 탭 6개, 무기 8개 장착, 기록 20행, 설정 저장, 영웅전 10개, 신규 역사 이미지.
- 이름 ‘하늘’, 군단 ‘푸른 새벽 군단’, 초상·색상·문장·장비를 편집해 저장하고 새로고침한 뒤 유지되는 것을 확인했다. QA가 만든 이 설정·전적은 최종 전달 화면에서 기본값으로 정리한다.

### 실제 전투 완주

[`tools/ego-play-verification.mjs`](../tools/ego-play-verification.mjs)는 UI 클릭·키보드·마우스를 사용한다. 관찰용 상태를 읽어 이동 방향을 선택하지만 적의 생명력이나 게이지를 강제로 바꾸지 않는다. 쉬움·2배속·장궁으로 언성 전투를 완료했다.

- 최종 기록: 게임 시간 약 8.6초, 개인 격파 97명, 지휘관 체력 2695/3000, 적 유효 전력 1%, 승리.
- 이는 밀집한 적에게 기술을 연계한 영웅 무쌍전의 빠른 완주 사례다. 전술전은 개인 공격력이 40%이므로 같은 난이도를 가정하지 않는다.
- [`evidence/browser-playthrough.json`](evidence/browser-playthrough.json)에 실제 진행·카메라 이벤트·결과를 저장했다.
- 승리 결과와 업적을 확인하고 사령부 복귀 후 기록이 유지되는 것을 검사한다.

### 모바일과 화면

[`tools/ego-mobile-verification.mjs`](../tools/ego-mobile-verification.mjs)로 작은 화면을 검사했다. 이름만 있는 터치 버튼이 아니라 pointerdown/keyup 흐름을 통해 영웅이 실제 이동하는지 확인했다. 가로 전투에서는 세로 화면 권고 배너를 숨겨 명령 버튼을 가리지 않는다.

[`evidence/browser-mobile-checks.json`](evidence/browser-mobile-checks.json)에 두 화면의 실제 너비와 가로 넘침, 터치 버튼 표시, 이동 전후 좌표를 기록했다.

## 검사 중 수정한 문제

1. 미니맵의 아군 진영 숫자가 색상 분기와 달라 적군 색으로 표시되던 문제.
2. 터치 이동용 키 이벤트가 전파되지 않아 영웅이 움직이지 않던 문제.
3. 강을 다리 바깥으로 건너던 병사·회피 충돌 문제.
4. 공격 목표를 달성하지 않고 제한 시간에 병력 우세만으로 승리하던 문제.
5. 자동 연출을 끄면 수동 영웅 집중도 동작하지 않던 문제.
6. 전술 지도에서 복귀한 뒤 CSS 지도 상태가 다음 전투에 남던 문제.
7. 저장 전 지휘관 편집의 색상·초상이 실제 저장 객체를 바꾸던 문제.
8. 급하게 여러 무기를 선택하면 알림이 화면 전체에 쌓이던 문제.
9. 가로 모바일에서 이동 버튼의 위치와 안내 배너가 조작부를 가리던 문제.
10. 무쌍 기술이 자기 타격으로 사용한 게이지를 즉시 다시 채우던 문제.
11. 결과 창 닫기가 전투 종료 후 빈 조작 화면을 남기던 문제.
12. 지연된 이전 결과 창이 새 출전에 표시될 수 있던 문제.

## 재현과 후속 검사

브라우저 검사 스크립트에는 이번 세션의 작업 공간 ID `4`와 페이지 `p2`, 로컬 URL이 들어 있다. 새 세션에서 실행할 때는 해당 Ego Lite 작업 공간·페이지로 바꿔야 한다. 스크립트는 일반 Node 단독 실행용이 아니며 `ego-browser nodejs`로 실행한다. 브라우저 전체 캐시나 다른 사이트의 저장 데이터를 지우지 않는다.

대규모 병력·고급 병종·새 목표·다른 장비를 추가한 후에는 해당 로직 테스트와 대표 브라우저 완주를 다시 실행한다. 현재 수치·지형·복합 목표의 차이는 `01`, `03`에 명시되어 있으므로 원작과 완전한 동등성 인증으로 해석하지 않는다.

## 최종 프로덕션 확인

`npm run build`로 만든 `dist`를 `http://localhost:4173/`에서 열어 HTTP 200, 실제 WebGL 전장, 기술 사용 후 사령부 복귀, 남은 기술 자막/알림 제거를 확인했다. 로딩된 리소스는 모두 동일한 로컬 origin으로, 외부 글꼴 요청이 없다. 전달 화면은 기본 지휘관 ‘새벽’과 초기 전적으로 정리했다.

- [`evidence/browser-production-check.json`](evidence/browser-production-check.json): 최종 빌드 실행·로컬 리소스·초기 전적 확인.
- [`evidence/browser-progress-check.json`](evidence/browser-progress-check.json): QA 설정 정리 전 승리와 업적 저장 유지 확인.
- [`evidence/production-build.txt`](evidence/production-build.txt): 최종 빌드 결과.

로컬 미리보기 주소는 개발 장비에서만 유효하며 공개 배포 URL은 아니다. 배포가 필요하면 `dist`를 정적 호스팅에 올리면 된다.
